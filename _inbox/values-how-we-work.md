# How We Work — Values, LIVED (not showcased)

> Aamir (2026-06): *"Our values are not just for the sake of showcase on the website."* This is
> the content source for a **"How we work / How we deliver"** section (About + reinforced on
> Services/Home). **The governing principle: present values as SPECIFIC, CHECKABLE BEHAVIORS &
> OUTCOMES — never a generic "Integrity/Excellence/Innovation" values poster.** A company whose
> core value is "real substance over hype" must present its values *without* hype. Form = content.

## Why NOT a generic values page
A "Our Values" list of abstract nouns is interchangeable, ignored, and (for THIS brand) a
self-betrayal — decorative values are the opposite of lived ones. Instead, **demonstrate** the
values through observable delivery behaviors. This is the same "trust via specificity, not
adjectives" principle as the reproducible benchmarks and honest status labels. It's also the
**lived reality behind the ISO certs** (cert = formal proof; these behaviors = what it means
day to day). Pair them.

## The lived values, as checkable behaviors + outcomes (from Aamir's examples)

| Value (lived) | What we actually do | The outcome (honest, calibrated) |

## Honesty calibration (Governing Rule #1) — use Aamir's OWN hedges
- ✅ "**Most of the time / as a rule / typically** clears first-pass" — NEVER "always" (he himself
  qualifies: "unless the client is extremely picky"). The hedge is what makes it believable.
- ✅ "Defect counts **fall over a project**" — not "zero bugs."
- ✅ "Systems people **actually use**" — a humble user-outcome metric, not "world-class performance."
- ❌ No unbacked superlatives; no "100% first-time-right"; no invented metrics. If we can cite a
  real number later (first-pass approval rate, defect-trend), even better — but only if true.
