The languageResearch · in development

Indigo

A Go superset. Every valid Go file is already valid Indigo, so you opt in feature by feature — and it compiles to clean, idiomatic Go you read in the diff.

you write · main.indigo
func load(id) {
    user := fetch(id)!
    tier := user.Pro ? "pro" : "free"
    names := users |filter: $.Active |map: $.Name
    return render(tier, names)
}
→
it ships · main.go idiomatic
func load(id int) (string, error) {
    user, err := fetch(id)
    if err != nil {
        return "", err
    }
    tier := "free"
    if user.Pro {
        tier = "pro"
    }
    var names []string
    for _, u := range users {
        if u.Active {
            names = append(names, u.Name)
        }
    }
    return render(tier, names), nil
}
“

One contract: no output is better than wrong output. If a feature can't preserve Go's exact behaviour — side effects, short-circuiting, defer ordering, panic timing — it's rejected, not faked. So you read the diff and ship it, or throw Indigo away and keep the Go. No runtime of its own.

UExL

An embeddable expression engine — the regex of expression evaluation. A real parser → compiler → VM, not a tree-walker: compile once, evaluate thousands of times, same semantics everywhere it's embedded.

expressions
# pipes instead of nested calls
orders |filter: $.paid |sum: $.qty * $.price

# explicit, safe semantics
user.plan ?? "free"      # null/absent only
account?.owner?.email   # no panic on nil

# Excel-familiar, embeddable anywhere
price > 100 and status in ["paid", "trial"]
Zero allocations on the hot path

String-match path, same hardware. Timings vary run to run — the allocation count doesn't, and that's the moat.

The query languageResearch · used in our production

AddressQL

A URL-native, backend-neutral query language — SQL-like power you can paste into a browser address bar. Filtering, projection, sorting and pagination as one readable, cacheable query string.

a real query · one GET request
GET /api/articles
  ?query=and(eq(status,open), has(author, eq(country,us)))
  &select=title, author.name, count(comments)
  &sort=-publishedAt
  &limit=20
“

Parenthesized prefix syntax means no precedence ambiguity; five independent params (query, select, sort, limit, offset) keep concerns separated; typed literals (d() dates, decimal(), uuid()) mean no silent string coercion. And because the canonical form is deterministic, identical intent produces an identical URL — so CDN caching and URL signing work with no client-side normalization. The same query string runs against MongoDB today and SQL tomorrow.

Honest status: internal, and used in our own production — we send AddressQL queries from the browser and run them against MongoDB behind our APIs. The specification is v1; portability specs for Go, JavaScript and Rust are written; the Go reference library is pre-public. Per our link-dark rule, no repository link appears here until there is a public repository to read. The deeper write-up lives on the Standards page.

The markup languageIn development · coming

PressML

A markup language for the printing press side of software: PDFs, books, reports and invoices, written the way web developers already think — HTML/CSS-style markup, aimed at print.

Documents that must print well — paginated, styled, repeatable — are still produced with tools that fight you. PressML applies the web's familiar authoring model to that problem. It is in active development and not yet public, so this entry is deliberately short: no syntax to show until there is a spec you can read, no links until there is a repository to open. When it ships, this section becomes a real one.
