Indigo

A Go superset. Every valid Go file is already valid Indigo, so you opt in feature by feature — and it compiles to clean, idiomatic Go you read in the diff.

you write · main.indigo
func load(id) {
    user := fetch(id)!
    tier := user.Pro ? "pro" : "free"
    names := users |filter: $.Active |map: $.Name
    return render(tier, names)
}
→
it ships · main.go idiomatic
func load(id int) (string, error) {
    user, err := fetch(id)
    if err != nil {
        return "", err
    }
    tier := "free"
    if user.Pro {
        tier = "pro"
    }
    var names []string
    for _, u := range users {
        if u.Active {
            names = append(names, u.Name)
        }
    }
    return render(tier, names), nil
}
“

One contract: no output is better than wrong output. If a feature can't preserve Go's exact behaviour — side effects, short-circuiting, defer ordering, panic timing — it's rejected, not faked. So you read the diff and ship it, or throw Indigo away and keep the Go. No runtime, no lock-in.

UExL

An embeddable expression engine — the regex of expression evaluation. A real parser → compiler → VM, not a tree-walker: compile once, evaluate thousands of times, same semantics everywhere it's embedded.

expressions
# pipes instead of nested calls
orders |filter: $.paid |sum: $.qty * $.price

# explicit, safe semantics
user.plan ?? "free"      # null/absent only
account?.owner?.email   # no panic on nil

# Excel-familiar, embeddable anywhere
price > 100 and status in ["paid", "trial"]
Zero allocations on the hot path

String-match path, same hardware. Timings vary run to run — the allocation count doesn't, and that's the moat.
